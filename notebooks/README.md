# Notebook order

Run the notebooks in numeric order using the existing persistent
`qwen-taboo-jlens` kernel:

1. `00_environment_smoke_test.ipynb` — lightweight environment/artifact check.
2. `01_gold_blue_behavior.ipynb` — exact artifact gate, base + Gold load and
   first manual smoke gate.
3. `02_base_jlens_sanity.ipynb` — official base-model J-Lens sanity, then Blue
   smoke and expanded published-prompt behavior gate.
4. `03_gold_blue_lens_sweep.ipynb` — runs the activation job directly in small,
   resumable notebook batches with visible per-layer progress.
5. `04_gold_blue_analysis.ipynb` — CPU tables and saved figures.

The larger confirmatory workflow is intentionally separate from that pilot:

6. `05_gold_blue_moon_validation_sweep.ipynb` — a state-aware GPU run over 30
   standard + 10 direct **validation-only** prompts for Gold, Blue and Moon. In
   the persistent kernel it verifies and reuses Qwen, the tokenizer, Gold,
   Blue, and J-Lens from notebooks 01–02, then loads only Moon. It masks every
   token ID emitted in each response before every LL/JL ranking, saves
   paper-style response averages, and records semantic token roles and exact
   response-relative positions across all layers.
7. `06_gold_blue_moon_validation_analysis.ipynb` — CPU-only Pass@10,
   Majority@10, accuracy, layer/role maps, paired LL/JL comparisons, and a
   frozen validation-selected exact layer/position specification for a later
   test.
8. `07_qwen36_20_adapter_test_sweep.ipynb` — the full resumable held-out test
   run: 100 standard + 100 direct prompts under all 20 word-specific Qwen 3.6
   Taboo adapters, with LL/J-Lens on every measured token and source layer. It
   reuses the model and J-Lens already loaded in the notebook 01–05 kernel.
9. `07_1_qwen36_base_test_control.ipynb` — the matched base-model control. Run
   it after notebook 07 in the same live kernel; it disables every LoRA and
   processes the same 200 test prompts once, preserving all-layer/all-position
   LL/J-Lens candidate scores and exact response-average ranks for all 20 words.
10. `08_qwen36_20_adapter_test_analysis.ipynb` — CPU analysis of the full test
   run: paper-style Accuracy/Pass@10/Majority@10, robust rank/probability
   metrics, masking sensitivity, layer × token maps, per-adapter heterogeneity,
   decoded internal top-token inspection, 20-way cross-secret specificity, and
   paired matching-adapter-versus-base controls.
11. `09_adapter_specific_jlens_refit.ipynb` — conditional follow-up after the
    notebooks 07–08 are complete and notebook 07 is idle. It starts with Rock
    as one representative adapter; the user enters one source layer selected
    from notebook-08 analysis. It fits the first 2 of the same 100 neutral
    WikiText sequences to measure runtime, prints an n=100 estimate, and waits
    for approval before resuming the identical checkpoint through n=100. It
    then compares Logit Lens, the public base-model J-Lens and Rock's refitted
    J-Lens. A second adapter is optional and disabled by default.

Notebook 01 prints an immutable `RUN_ID`. Paste exactly that value into
notebooks 02–04. Do not restart or switch the kernel after loading the 27B
model. Do not run notebook 03 until all three behavior reviews and the
base-sanity review in notebook 02 pass.

The checked-in notebooks are generated by
`scripts/build_gold_blue_notebooks.py`; edit that readable source and rebuild
rather than hand-editing notebook JSON.

Notebooks 05–06 are generated by `scripts/build_validation_notebooks.py`.
Notebook 05 creates its own `RUN_ID`, but should normally run in the same
persistent kernel after notebooks 01–02 so their expensive compatible objects
are reused. It has a clean-kernel fallback, but never silently loads a second
27B copy when a model is already present. Paste its `RUN_ID` into notebook 06.
Do not use test prompts while tuning the selection; test is reserved for one
later run with the saved `frozen_validation_selection_for_test.json`.

Notebooks 07 and 08 are generated by `scripts/build_test_notebooks.py`.
Notebook 07 intentionally has no clean-kernel fallback for the base model: run
it in the same live kernel as notebook 05, where it loads only missing LoRA
adapters. Its atomic per-sequence files make the 4,000-sequence test sweep
resumable. Notebook 07.1 is a separate visible control notebook and reuses the
completed notebook-07 state without loading another base model.

Notebook 09 is generated by `scripts/build_adapter_refit_notebook.py`. It
reuses the existing persistent model kernel when compatible, or restores the
pinned base model, public lens, and selected adapter after a clean-kernel
restart. It must not run concurrently with notebook 07. Its official
`jlens.fit()` checkpoints are paired with a
corpus/adapter identity sidecar because the upstream checkpoint format does not
record those fields. The n=100 fits are exploratory layer-specific lenses, not
paper-equivalent replacements for the public n=1000 all-layer lens.

The model-facing implementation is intentionally visible in notebooks 01–03:
model and adapter loading, generation, activation recording, Jacobian
transport, unembedding, and rank calculations. Notebook 04 similarly keeps
metric construction and plots in cells. Helpers under `src/` remain the
tested CLI/automation path and handle mostly artifact I/O, review gates, and
optional unattended execution.

The full method, gates, metrics and artifact tree are documented in
`docs/GOLD_BLUE_PROTOCOL.md`.
